# MCP 호출 안전성 개선

MCP 클라이언트는 에이전트와 모니터링·런북 서버 사이의 통로다.
서버가 보낸 내용을 곧바로 진단 자료로 사용하는 대신, 입력·응답을 검사하고
호출이 끝나지 않을 때 대기를 제한한다.

## 바뀐 이유와 동작

| 상황 | 기존 동작 | 개선 동작 |
|---|---|---|
| 시스템 이름이 비었거나 인자 형식이 잘못됨 | 서버에 보낸 뒤 SDK/서버 오류 발생 | 보내기 전에 입력 오류로 거부 |
| MCP가 도구 오류를 표시함 | 첫 텍스트를 JSON으로 해석 | 오류 표시를 먼저 확인하여 진단 자료로 사용하지 않음 |
| 응답이 비었거나 JSON 객체가 아님 | IndexError·JSON 오류 등이 제각각 발생 | 일관된 응답 오류로 구분 |
| web-01을 요청했는데 다른 시스템의 수치가 옴 | 반환 데이터를 그대로 사용 | 요청·응답 시스템이 다르면 거부 |
| CPU가 문자열·NaN·무한대·범위 밖 수치임 | 별도 검증 없음 | 유한한 0~100 숫자인지 검사 |
| 요청이나 연결 사용 대기가 끝나지 않음 | 클라이언트 전체에 일관된 제한 없음 | 개별 작업에 기본 10초 제한 |
| 시작 도중 두 번째 MCP 서버 연결이 실패함 | 앞서 열린 자원 정리가 보장되지 않음 | 이미 연 연결을 정리하고 초기 상태로 복구 |

`agent/mcp_client.py`가 검사·시간 제한을 담당하고,
`agent/mcp_errors.py`의 `MCPCallError`가 영구 오류의 종류를 구분한다.
호출자에게 반환하는 오류 메시지에는 응답 전문이나 서버 내부 오류 내용을 넣지 않는다.

## 응답 검사

모니터링 응답은 다음을 만족해야 한다.

- 요청한 시스템 이름과 같음.
- 상태가 `healthy`, `degraded`, `down`, `unknown` 중 하나임.
- CPU·메모리가 bool이나 문자열이 아닌 유한한 0~100 숫자임.
- 조회 시각이 날짜와 시간을 포함한 유효한 값임.
- 알림이 문자열 목록임.

Tool의 구조화 응답과 기존 JSON 텍스트 응답을 지원한다.
Resource·Prompt도 빈 응답이나 지원하지 않는 콘텐츠를 검사한다.
여러 텍스트 조각이 있으면 첫 조각만 버릇처럼 선택하지 않고 함께 반환한다.

Tool 인자는 JSON 형식으로 검증한 독립 사본을 사용한다. 중첩 딕셔너리·목록까지
복사하므로 잠금을 기다리거나 응답을 받는 동안 호출자가 원본을 변경해도 전송할
내용과 응답 검증 대상은 바뀌지 않는다. 튜플은 JSON 전송 형식에 맞춰 목록이 된다.
Prompt는 문자열 키·값만 허용하므로 중첩 JSON 순회 없이 검사하고 복사한다.
응답의 오류 표시는 공통 요청 경계에서 한 번 검사하며, 잠금 획득 후 연결이
여전히 유효한지 다시 확인하는 검사는 유지한다.

이 검사는 수치의 형식·범위·대상 일치를 확인한다. MCP 서버가 실제 현실을
정확히 관측했는지까지 증명하지는 않는다.

## 내부 진단 로그

SDK·전송 요청 오류와 시작·정리 실패는 Python의 `agent.mcp_client` 로거에
WARNING으로 기록한다. 서버명, 작업명, 예외 종류, 정수 SDK 오류 코드,
정리 실패 여부만 남기며, 예외 메시지·traceback·입력 인자·응답 전문은 담지 않는다.
시작 오류 뒤 정리도 실패하면 두 실패를 각각 기록하고 최초 오류를 호출자에게
전달한다. 전체 연결 정리 로그의 서버명은 `all`로 표시한다.
별도의 로그 파일이나 외부 전송 서비스는 추가하지 않는다.

## 시간 제한과 재시도는 다른 역할

```python
client = MCPClient()                       # 개별 작업 제한: 기본 10초
client = MCPClient(timeout_seconds=2.0)    # 필요할 때 코드에서 설정
```

Tool 호출, Resource 읽기, Prompt 요청, 목록 조회에 적용한다. 공유 연결을
사용하기 위해 lock을 기다리는 시간도 포함한다. LLM을 포함한 진단 전체를
10초로 제한하는 설정은 아니다.

- **timeout:** 끝나지 않는 한 번의 대기를 중단한다.
- **retry:** 일시적인 timeout이 발생했을 때 다시 시도한다.

기존 `agent/retry.py`는 유지한다. `with_retry`로 감싼 호출은 timeout에서만
최대 3회 시도하며, 기존 대기 시간은 0.3초·0.9초다. 각 시도가 10초 제한에
도달한다면 총 소요 시간은 대략 31.2초와 정리·스케줄링 비용이 된다.
Resource·Prompt 호출에 새 재시도 루프를 추가하지 않는다.

SDK가 전용 MCP timeout 오류로 전달하는 경우도 기존 재시도가 알아볼 수 있는
`TimeoutError`로 연결한다. 잘못된 인자·서버 오류·잘못된 응답은
`MCPCallError`로 실패하며 같은 요청을 반복하지 않는다.

사용자의 요청 취소는 timeout으로 바꾸지 않고 전파한다. timeout·취소 후에는
자신이 잡았던 lock을 풀어 다음 요청을 막지 않는다. 대기하던 요청이 시간 초과되어도
먼저 연결을 사용 중인 다른 요청을 취소하지 않는다.

시작·종료에도 시간 제한을 적용하고, 시작에 실패하면 이미 열린 자원을 정리한다.
정리 중 예외가 발생하면 실제로 연결이 모두 닫혔다고 단정하지 않는다.
MCP SDK의 연결은 생성한 비동기 작업에서 닫아야 하므로 기존 FastAPI lifespan의
생성·종료 구조를 유지하고, 별도 작업을 만드는 `wait_for` 대신 `asyncio.timeout`을
사용한다. 이 구현은 Python 3.11 이상에서 사용할 수 있다.
timeout 이후 SDK의 프로세스 정리 시간이 추가될 수 있으므로 실제 경과 시간이
설정값과 정확히 같다는 뜻은 아니다.

## 이번 범위

미등록 시스템의 `unknown` 응답은 기존 계약대로 유지한다. 이를 정상 상태로
바꾸지 않으며, 시스템을 되묻거나 다른 대상으로 바꾸는 대화 기능은 추가하지 않는다.
미등록 시스템을 진단하기 전에 사용자에게 확인하는 기능은 별도 대상 확인 단계다.

오류를 HTTP/SSE 화면에 친절하게 표시하는 기능, RAG, 전문 에이전트, 모델 최적화는
이번 변경에 포함하지 않는다. 현재 계층에서 잘못된 자료를 반환하지 않고
명확한 오류를 전달하는 데 집중한다.

## 검증 방법

```sh
PYTHONDONTWRITEBYTECODE=1 LANGSMITH_TRACING=false LANGCHAIN_TRACING_V2=false \
  .venv/bin/python -m unittest discover -s tests -p 'test_mcp_safety.py' -v

PYTHONDONTWRITEBYTECODE=1 LANGSMITH_TRACING=false LANGCHAIN_TRACING_V2=false \
  .venv/bin/python -m unittest discover -s tests -v
```

외부 LLM 호출과 LangSmith 전송 없이 입력·오류 응답·수치 검증·timeout·취소·
재시도·연결 정리를 확인한다. 로컬 stdio MCP를 사용하는 통합 확인도 포함한다.
속도나 답변 정확도가 개선됐다는 성능 평가는 이 테스트와 별도로 수행해야 한다.

2026-10-20 검증: 기존 29개와 신규 안전성 27개를 합한 **56개 테스트 통과**.
실제 stdio timeout 이후 같은 연결의 다음 호출, 시작 timeout 이후 자식 프로세스
종료·재시작, 기존 v2 진단 흐름을 확인했다. 환경은 Python 3.14.7,
MCP SDK 2.3.0, FastMCP 4.1.1이며 다른 SDK 버전의 실제 통합 실행은 확인하지 않았다.

후속 보완에서는 중첩 Tool 인자·Prompt 인자·응답 검증 대상의 사본 유지와
오류 로그의 메타데이터 및 민감한 원문 제외를 검사한다. 실제 시작 timeout
테스트는 두 자식 프로세스의 PID 파일을 준비 신호로 사용한 뒤 클라이언트의
실제 타이머를 만료시킨다. 정상 후속 요청과 종료에는 별도 여유 시간을 적용한다.

2026-10-20 후속 보완 검증: 전체 **60개 테스트 통과**(기존 56개 + 신규 4개).
기존 SDK timeout·시작/정리 실패 테스트에도 로그 검증을 추가했다.
