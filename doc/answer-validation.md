# 진단 답변 내용 검증

v2의 `write → validate → finalize` 흐름에서 `agent/validation.py`의
`AnswerValidator`를 사용한다. `SupervisorDeps.answer_validator`로 교체할 수 있으며,
실행 환경에서 Validator 모델을 Writer와 독립적으로 설정한다. 기본 모델은 기존과 같다.
일반 대화와 대상 확인 질문은 이 진단 검증 경로를 실행하지 않는다.

## 모델 설정

| 백엔드 | Writer 설정 | Validator 설정 | 각각의 기본값 |
| --- | --- | --- | --- |
| OpenAI | `OPENAI_QUALITY_MODEL` | `OPENAI_VALIDATOR_MODEL` | `gpt-4o` |
| Ollama | `OLLAMA_QUALITY_MODEL` | `OLLAMA_VALIDATOR_MODEL` | `qwen3:8b` |

`.env` 또는 실행 환경변수로 설정한다. Validator 설정을 생략하거나 빈 값으로 두면
위 기본값을 사용하며, Writer 모델을 바꿔도 Validator 모델은 함께 바뀌지 않는다.
기존에 quality 모델을 재정의하여 두 역할에 사용했다면 Validator 변수에도 같은 모델을
명시해야 그 조합을 유지할 수 있다. 백엔드는 기존 `LLM_BACKEND`를 함께 따른다.
기존 공급자 어댑터가 지원하는 모델을 지정해야 하며, 모델별 호출 형식은 변경하지 않는다.
서버 재시작 후 `/health`의 `quality_llm`과 `validator_llm`으로 적용 값을 확인한다.
Ollama에서 새 Validator 모델을 선택하면 먼저 `ollama pull <모델명>`으로 설치한다.

`fake`는 기존 의미 검사 시뮬레이션을 유지하고, v1은 Validator를 생성하지 않는다.
직접 `SupervisorDeps`를 조립할 때는 `answer_validator`로 검증기를 주입한다.
생략한 경우 그래프는 기존처럼 `quality_llm`을 사용한다.

## 검증과 재작성

1. 형식, 대상 누락, 명시적으로 표기된 시스템별 CPU·메모리 수치, 일부 지속 표현과
   선택된 런북의 CPU·메모리 수치 조건을 코드로 검사한다. 조건부 절차의 임계값을
   현재 관측 수치로 비교하지 않는다.
2. 규칙 위반이 없으면 모델이 수치, 조치 조건, 시간상 주장, 근거성, 요청 충족,
   사용자 제보와 현재 관측의 차이를 각각 검토한다. 원문과 조회 시각을 함께 제공한다.
3. 여섯 항목을 모두 반환해야 하며, 판정·인용 문장·근거 ID·수정 지시를 코드로
   검사한다. 판정 누락, 잘못된 JSON, 존재하지 않는 인용·근거는 검증 불가다.
4. 반려 시 문제 문장과 근거·수정 지시를 Writer에 전달한다. 최대 3번 작성한다.
5. 3회 반려 또는 의미 검토 불가/오류/30초 제한 도달 시, 생성 초안을 합격시키지 않는다.
   코드로 만든 제한된 답변에 확인된 상태·CPU·메모리·조회 시각과 추가 확인 요청만 담는다.
   사용자 요청 취소는 그대로 전파한다.

`Validation` 이벤트는 `status`(passed/rejected/limited), `review_status`,
issues, checks, usage, elapsed_ms, review_called를 제공한다. 제한된 답변은 의미 검사
합격과 구분한다. 검증 비용은 기존 cost_usd에 누적되며 이는 기존 가상 단가 계산이다.
공급자 토큰과 실제 청구 금액은 별도의 평가 지표다.

## 화면과 저장

진단의 `AnswerToken`에는 `phase=draft`가 붙는다. 화면에 검증 전 초안임을 표시하며,
반려된 초안에는 사용하지 말라는 표시를 남긴다. `FinalAnswer.validation_status`로
검증 완료와 제한된 답변을 구분한다. 세션에는 최종 답변만 저장한다.
초안은 생성 중 화면에 보이므로 최종 답변 전에 이를 사용하지 않아야 한다.
OpenAI의 실제 토큰 스트리밍 추가와 화면 재배치는 이번 변경 범위가 아니다.

## 한계와 검증

코드 규칙은 명시적인 표기 일부를 다루며 모든 자연어를 해석하지 않는다. 의미 검토 모델도
누락·오탐이 가능하므로 검사 통과를 진단의 절대적 정확성으로 해석하지 않는다.
`fake` 백엔드는 규칙 검사와 흐름 테스트용이며 의미 검사 응답은 시뮬레이션이다.
런북 검색이나 수집 범위를 늘리지 않으며 부족한 근거를 새 사실로 만들지 않는다.

`sh sh/test.sh`로 외부 모델 호출 없이 회귀 검증한다. 수치 경계, 조건부 권고,
시스템별 수치 혼합, 다른 지표의 추세 알림, 검증 응답 오류·취소·시간 초과,
재작성 피드백·횟수 제한, HTTP/SSE 최종 응답과 세션 저장을 검사한다.
실제 모델의 진단 품질은 별도의 동일 조건 평가와 수동 판정으로 확인한다.

## 내용 검증 도입 당시 검증 결과

- 전체 오프라인 회귀: 391 tests + 108 subtests 통과.
- 최종 실제 평가 9/9 요청과 원본 LangSmith 입력·답변·토큰 대조 통과.
- 기존 수동 기준의 엄격 답변 통과는 4/9→6/9, 진단 사례만 보면 0/4→2/4다.
  이는 동일한 공개 소규모 회귀셋에서 개발 중 반복 확인한 값이며 별도 holdout 결과가 아니다.
- C01 지속 상태 단정과 C03 제보·정상 관측의 차이 누락이 개선됐다.
  C04는 89% 즉시 재시작을 권하지 않지만 heap near limit 알림 누락으로 엄격 판정은 실패다.
  C02의 CPU 런북·관계 설명 누락, C06의 미등록 대상 설명 누락도 남았다.
- 최종 9요청 평균 HTTP 지연 4.81→6.90초, 공급자 OpenAI 토큰 7,328→23,384,
  LangSmith 추정 비용 약 $0.0203→$0.0829. 실제 청구액은 미확인이다.
- 검증 모델은 일부 정상 표현을 반려할 수 있다. 최종 C04에서도 알림 추세를 근거 부족으로
  판단한 반려가 관찰됐다. 제한된 답변·재작성은 안전장치이며 의미 검증의 무오류 보장이 아니다.
- 실제 Ollama 의미 검토는 이번에 측정하지 않았다. Ollama 어댑터는 HTTP 대역으로 검증했다.
